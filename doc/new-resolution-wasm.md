# New-resolution WASM investigation

## Implemented fixes

The new-resolution tests inherit `:js` from the root test configuration. With
`:wasm`, lowering emits WASM-specific intrinsic references, but the harness also
tries to execute that same IR as JavaScript. The WASM directory's `.mls` now
uses `:!js` while retaining the inherited language configuration. Imported
directives recognize the lexer's `:!` token as well as `:`. Compiling a nonempty
block with both backends enabled now emits a warning.

Explicit `instance.Class#member` and `Class::member` now share `NewSel` with an
optional class expression. Elaborating a projection registers class-shape
listeners; symbolic class lookup waits for definition completion and chooses the
class interpretation independently of term overloads. Class aliases can supply
constructor shapes. Applied instances are rejected as projection classes.
Completed-symbol class interpretation is shared with explicit `new`, whose
accepted class-expression forms remain unchanged.

Instance-member lookup uses completed class and extension shapes, retaining
capture marks for inherited members and publishing the selected member's shape.
Recorded projection candidates retain class identity and capture marks, and
ambiguity checks also account for distinct wildcard receivers. Different classes
inheriting the same member do not become an unambiguous projection. Repeated
notifications and repeated opens of the same receiver are deduplicated.

Lowering validates recorded candidates and uses the ordinary selection paths
for reads, calls, and assignments. It neither queries syntax members nor
selects definitions from an overload set. Symbol queries also reject ambiguous
projection classes. The instance is evaluated once; assignment coverage checks
this with a receiver that increments a counter.

`Class::member` keeps its lambda elaboration. Its forwarded argument tuple is
resolved through shape listeners, including when arguments arrive after the
method shape. Argument extraction retains the tuple's capture marks, and rest
parameters publish and cache their tuple shapes, including empty tuples.

## Coverage and remaining limitations

`Projections.mls` covers both syntaxes, forward class definitions, class/term
overloads, aliases, qualified names, inherited methods, fields and assignments,
captured classes, invalid classes, missing members, distinct wildcard receivers,
shared inherited members, repeated opens, and forward wildcard sources.

`WasmMethodResolution.mls` now runs direct projections without `:fixme`, including
mixed projected and ordinary method calls. `BackendFlags.mls` checks the warning
and disabling JS through the directory configuration.

Two independent limitations remain explicit regressions:

- WASM cannot compile the anonymous function generated by `Class::member` yet.
  The final block in `WasmMethodResolution.mls` retains `:fixme` for the backend's
  anonymous-function/static-call diagnostics; member resolution succeeds.
- Call-site shape correlation is incomplete for nested forwarding calls.
  `CallSiteShapes.mls` reproduces the ambiguity both with ordinary functions and
  with a projected function. These cases remain `:fixme`; the resolver does not
  choose an arbitrary member to suppress the ambiguity.

Method calls across separate REPL blocks are being handled on another branch
and are outside this work.

## Optional harness follow-up

If tests need both JS and WASM execution, lower separately for each target and
keep their backend scopes and session state separate. Respect the MIR rule that
each definition symbol owns at most one current IR definition: use isolated
compilation state or refresh symbols rather than retaining two IRs that mutate
the same symbols' `irDefn` fields. Binding the WASM support module in the JS
scope is insufficient: that module supplies compilation/instantiation helpers,
not JavaScript implementations of all WASM intrinsics.
